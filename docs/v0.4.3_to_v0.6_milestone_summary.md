# AKsignal 阶段性工作总结（v0.4.3 → v0.6）

> 状态：阶段性总结（2026-08-04）
> 范围：从 v0.4.3 每日信号链，到 v0.6 组合模拟与组合构建实验，共 16 个提交。

---

## 0. 一句话定位

**v0.4.3 回答「今天买什么」；v0.6 回答「这套信号过去真的有效吗、放进账户能赚多少」。**

中间补建了完整的四层研究/回测链路：**Replay → Event Study → Trade Simulation → Portfolio Simulation**。

---

## 1. 阶段一：v0.4.3 收尾

### 1.1 Selection 去在线化（离线、确定性）

- **问题**：Selection 原来对 33 个资产逐个联网抓取（新浪/东财/AKShare）、5 次重试、切源、缓存降级，最坏跑二三十分钟；且用到了目标日之后的最新/盘中数据（look-ahead）。
- **改动**：
  - 个股趋势改为预计算产物 `outputs/selection_inputs/stock_metrics_{trade_date}.parquet`（`select inputs` 构建）
  - ETF 指标强制复用 Layer① rotation，不再重复抓取
  - `select run` 默认禁止联网；缺失输入按 `data_status=missing / selection_status=unavailable` 局部降级，不阻塞整体
  - 新增 `coverage` 报告（etf_reused / stock_inputs_loaded / selection_coverage / degraded_assets）
  - `compute_trends` 新增 `as_of_date` 截断，消除 look-ahead
- **效果**：`make select` 从分钟级降为 0.2s，Online fetches = 0。

### 1.2 run-day 末端 Final Validation

- `make run-day` 新增 `select-inputs → select → run-day-check`。
- `final-check` 汇总三层产物 + run 警告，输出：
  ```
  Run completed successfully
  trade_date : 2026-08-03
  status     : CONFIRMED
  action     : BUY
  warnings   : 2 stock drilldowns failed
  ```
- 产物缺失 → `Run completed with errors`，退出码 1。

## 2. 阶段二：v0.5.0 Historical Replay

### 2.1 核心判断

> 瓶颈不是回测引擎，是**信号历史**。AKSignal 自己的信号产物只有约 2 周历史，「过去严格按信号执行」这段历史必须用现价数据按相同规则**重放**。

### 2.2 交付

- **`src/research/`** 子包：`replay/`（engine + cli）、`signals/`（historical_signals schema + config_hash）、`validation/`（parity）
- **单日期重放** `replay single --date`：纯离线，三层（ETF rotation / 行业确认 / Selection）复用同一套已通过 parity 的规则函数
- **Parity 验收** `replay parity --date`：重放结果与正式产物逐字段对比——数值容差、状态字段必须完全一致；缺正式产物层标记 not_checked
- **区间重放** `replay range --start --end`：
  - `--resume`（相同 rule_version+config_hash 的已完成日期跳过）、单日失败不终止、按主键去重、失败/降级/跳过入 manifest
  - 不覆盖正式 daily pipeline 产物（`persist=False` + `persist_processed=False`）

### 2.3 验证基线

| trade_date | Layer1 | Layer2 | Layer3 |
|---|---|---|---|
| 20260803 | 1259/1259 | 12/12 | 25/25 |
| 20260731 | 1255/1255 | 12/12 | 无正式 selection |

区间重放在既有正式日期与单日期重放完全一致（零字段差异）。

### 2.4 统一 schema

```text
trade_date / signal_origin / entity_type / entity_code / theme / layer /
rps15 / trend_score / trend_state / confirmation_status / selection_status /
recommended_action / signal_reason / source_trade_date / data_status /
rule_version / config_hash
```

## 3. 阶段三：v0.5.1 Event Study

### 3.1 定义

事件 = **状态转换**（非每日快照）：
- Layer1 ETF：trend_state 进入 {BUY_CANDIDATE, STRONG_WATCH}（off→on）
- Layer2 行业：confirmation_status 进入 {观察, 强势}
- Layer3：selection_status 进入 RECOMMENDED

### 3.2 指标

5/10/20/60 日前向收益、基准超额、胜率、均值/中位、MFE/MAE、非重叠样本计数；区分 entity_type / theme。
基准 = 同实体宇宙横截面中位前向收益（离线、全历史，替代过期 HS300 缓存）。

### 3.3 核心发现（2024-01 → 2026-05，40,044 事件）

| 事件 | 60 日均值 | 胜率 | 超额 |
|---|---|---|---|
| AI 基础设施行业确认 entry | +13.8% | 69.3% | +12.8% |
| AI 基础设施 ETF 趋势门 entry | +9.4% | 64.1% | +6.5% |
| 高现金流行业确认 entry | +1.6% | 54.3% | +0.7% |
| AI ETF exit（退出后） | +9.6% | 66.5% | +6.5% |

**结论**：信号确实有前向收益价值；退出后仍上涨 →「信号退出」偏早（动量未止）。

## 4. 阶段四：v0.5.2 Trade Simulation

### 4.1 交付

- **`src/backtest/trade/`**：`strategy/`（entry/exit）、`execution/next_open.py`（T+1 开盘）、`trades.py`（逐笔，独立等名义本金）、`metrics.py`
- **冻结约束**：持仓期间再次 entry 不重复开仓（按上一笔持仓了结日比较）；Exit 是 Strategy Policy 动作非 Selection SELL；缺下一交易日 → `unfilled`；fixed_horizon 按交易日；MA20 只用判断日当日及以前数据；费/滑点保留配置字段
- **第二轮稳健性** `backtest sensitivity`：固定持有期 / MA 参数 / 分年 / 分 ETF / 成本扫描
- **Universe 范围** `--universe-mode configured|theme-matched`（配置资产池 vs 全市场关键词），产物记录 universe_mode/size/config_hash

### 4.2 实盘（AI 基础设施 ETF，2024-01 → 2026-05）

| 退出策略 | 成交 | 胜率 | 均值收益 |
|---|---|---|---|
| **fixed_horizon (20d)** | 852 | 53.2% | +3.23% |
| ma20_exit | 1003 | 42.7% | +2.82% |
| signal_exit | 1657 | 41.3% | +0.56% |

### 4.3 四组矩阵（fixed_20）

| 组 | n | 胜率 | 均值 | PF | Top5占比 |
|---|---|---|---|---|---|
| AI theme-matched（74 只） | 852 | 53.2% | +3.23% | 1.98 | 19% |
| AI configured（8 只） | 121 | 50.4% | +2.69% | 1.75 | 91% |
| HC theme-matched（19 只） | 143 | 62.9% | +1.98% | 2.59 | 55% |
| HC configured（6 只） | 52 | 65.4% | +2.03% | 2.54 | 98% |

**结论**：
- 高现金流最稳健（三年全正、胜率 65%、PF 2.5）；AI 两模式 2024 均为负
- 固定资产池捕获大部分信号，但 ETF 贡献高度集中（AI 91% / HC 98%）→ 幸存者偏差风险高
- 固定持有期单调上升（非 10-30 平台）；MA 退出为典型趋势策略（中位负、PF~2.3、大盈利贡献 40%）
- signal_exit 成本敏感度最差（20bp 边收益几乎吃光）

## 5. 阶段五：v0.6 Portfolio Simulation & Portfolio Construction

### 5.1 命名与分层

正式定名 **Portfolio Simulation**（组合模拟）——有限资金下整个账户的表现，回答「整个账户好不好」，与 v0.5.2 Trade（一笔交易好不好）分层。

```
src/backtest/
    trade/            ← v0.5.2 一笔交易
        strategy/ execution/ trades.py metrics.py
    portfolio/        ← v0.6 整个账户
        engine.py     账户引擎（逐日撮合/盯市）
        allocation.py 仓位分配（equal-weight / max_positions / max_weight / deploy_ratio / score-weight）
        nav.py        NAV + 绩效 + 基准
        metrics.py    报告
        simulate.py   编排（单策略 + Core+Quality）
        construction.py 组合构建实验
```

主题级策略配置 `config/strategies.yaml`（策略规则按主题配置，不共用全局 Entry/Exit）：
AI 主策略 fixed_20（MA20 作对照）；HC 主策略 fixed_20。

### 5.2 资金规则（第一轮）

```text
initial_capital = 1,000,000
max_positions = 5
position_sizing = equal_weight
max_weight_per_asset = 20%
no_leverage / no_pyramiding / next_open / fee + slippage（5bp 单边）
不做 ATR
```

### 5.3 绩效修复（关键）

| Bug | 修复 |
|---|---|
| NAV 稀疏（只记事件日） | **完整交易日历日频**（562 天，无交易也记现金/权益） |
| 年化用记录数 | 按实际自然日跨度 `(365.25 / elapsed_days)` |
| Sharpe 稀疏非等间隔 | 仅用完整日收益，risk_free_rate=0 显式 |
| Calmar 连带高估 | 用修正后的年化 + 回撤 |
| 回撤漏谷底 | 完整日频 + 峰值/谷底/恢复日/持续天数 |
| 基准区间不一 | 统一日历（所有账户+基准同起止），基准统一 +41.96% |
| win_vs_bench 语义模糊 | 拆为 daily_outperformance_rate + rolling_20d_outperformance_rate |

基准默认切到**真 HS300 指数缓存**（覆盖检查，`--benchmark-fallback 510300` 仅显式回退）；新增 `data benchmark refresh` 在线刷新（回测本身离线）。

### 5.4 修正后五条净值线（2024-01 → 2026-05）

| 组合 | 累计 | 年化 | 回撤 | Sharpe | Calmar | HS300 超额 |
|---|---|---|---|---|---|---|
| AI-20 | +15.9% | 6.5% | -15.0% | 0.49 | 0.44 | -26% |
| AI-MA | +26.3% | 10.6% | -15.0% | 0.74 | 0.71 | -16% |
| HC-20 | +6.8% | 2.9% | **-4.1%** | **0.78** | **0.70** | -35% |
| Core+Quality-A | +30.1% | 12.0% | -21.3% | 0.66 | 0.56 | -12% |
| Core+Quality-B（60/40） | +19.8% | 8.1% | -13.0% | 0.62 | 0.62 | -22% |

### 5.5 组合构建实验（不改入场/出场，只改构建）

单维度扫描，基线 = 等权 / max5 / AI50 / cash100：

| 实验 | 结果 |
|---|---|
| Top-N（3/5/10） | 实体越多越好（top_10 18.4% > top_3 8.0%） |
| 等权 vs Score-Weight | score-weight 总收益翻倍（18.4%→30.1%）、超额 -23.6%→-11.9%，回撤扩至 -17.7% |
| Max Position（3/5/8） | **max_8 最优**（+21.6%、回撤 -8.0%、Sharpe 0.88、Calmar 1.1） |
| AI 比例（50/60/70） | 越高收益越高但 Sharpe 降；ai50 风险调整最优 |
| 现金比例（100/80/60） | 满仓收益最高，降现金只降收益 |

### 5.6 结论

> **5 组组合优化后全部仍跑输 HS300（最佳超额 -11.9%）→ 本区间问题在 Strategy 而非 Portfolio。**

组合构建只能改善风险调整（max_8）与原始收益（score-weight 的集中杠杆效应），无法把跑输基准的策略变成跑赢。价值在风险调整（HC Sharpe 0.78 / Calmar 0.70）与回撤控制，非原始超额。

## 7. 核心结论（对决策的影响）

1. **信号有价值**：AI 基础设施的行业确认（60 日超额 +12.8%）与 ETF 趋势门有真实前向收益
2. **signal 退出偏早**：中位持有 3 天，边收益被成本吃光——Exit 必须独立实验
3. **HC 是防守核心**：三年全正、胜率 65%、回撤 -4%、Sharpe 2.47
4. **AI 有周期性**：2024 全负，收益集中在 2025+——不能当防守用
5. **组合跑输 HS300**：即使组合优化（max_8 + score-weight）最佳超额仍 -11.9%——问题在 Strategy 不在 Portfolio

---

## 8. 工作流应用

- **每日**：照常 `make run-day`，读 `outputs/selection/tradable_candidates_{date}.html` 决策
- **策略评估**：任何规则改动（退出/主题/资产池）→ `replay-range` + `event-study` + `backtest trades|portfolio` 对比，不拍脑袋改
- **决策依据**：HC 防守（风险调整）、AI 进攻（接受回撤）、退出用 fixed_20 而非 signal_exit
- **诚实边界**：这套策略过去 2.4 年跑输 HS300；价值在风险调整与回撤控制。若要绝对收益，问题在 Strategy 层（入场/退出规则本身）尚未解决
