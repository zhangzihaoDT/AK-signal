> 这不是开发计划（见 `docs/v0.5_backtest_plan.md`），而是代码层的「现状事实 + 已知约束」。

## 0. 一句话

三层核心计算函数几乎全是纯函数（给定截断输入即得指定日横截面）；问题集中在 **CLI 层的隐式「最新日期」依赖** 与 **配置快照漂移**。单日期 replay 已实现并通过 parity（20260803 / 20260731）。

## 1. Layer ① ETF rotation

### 纯计算入口

| 步骤 | 函数 | 位置 |
| --- | --- | --- |
| 全量日行情合并 | `_load_all_raw(master)` | `src/etf_signal/cli.py` (private) |
| 技术指标 | `indicators.compute_indicators(daily)` | `src/etf_signal/indicators.py:23` |
| 横截面 RPS | `rotation.compute_rotation_metrics(combined, master)` | `src/etf_signal/rotation.py:148` |
| 逐日 RPS/rank | `rotation.compute_cross_sectional(...)` | `src/etf_signal/rotation.py:79` |
| 趋势状态 | `signal.compute_trend_state(...)` | `src/etf_signal/signal.py:34` |
| watchlist | `signal.build_trend_watchlist(indicators, master)` | `src/etf_signal/signal.py:85` |
| 账户映射 | `account.map_watchlist_to_account(watchlist, blacklist)` | `src/etf_signal/account.py:142` |

关键语义：
- `compute_rotation_metrics` 对传入 `combined` 的**最后一交易日**计算横截面（内部 `.iloc[-1]`）→ 给「截断到 D 的 combined」即得 D 日横截面。
- RPS 口径：`rps15/20/60 = 15/20/60 日收益的全市场百分位`（`rank(pct=True)*100`），货币/债券桶排除在排名外（`RANK_EXCLUDED_BUCKETS`）。
- `build_trend_watchlist` 把 rps15 舍入到 **1 位小数**（signal.py:146）——**account_candidates 的 rps15 是舍入值，rotation parquet 是全精度**。Replay 取 rps 必须从 rotation 侧取，才能与正式产物对齐。
- `compute_cross_sectional` 只保留尾部 `CROSS_SECTIONAL_TAIL=21` 行（rotation.py:58）——单日「最新」语义设计，**不直接产出全历史横截面**。

### 隐式「最新日期」依赖（Replay 必须绕过）

1. `cmd_calculate` 锚点：`--date → --target-date → _default_target_date()`（cli.py:154，按 16:30 时间推断）。
2. **`if max_avail < trade_date: trade_date = max_avail`（cli.py:1090）**——目标日无数据时静默回退到最近可用日。Replay 应显式传 date、不回退（或记录 actual）。
3. `cmd_account_mapping` 读**最新** watchlist 文件（`watchlist_files[0]`，cli.py:728）——非精确。
4. `daily_indicators.parquet` 是**滚动累积文件**（每次 calculate 覆写全量至锚点，cli.py:1143）——历史 watchlist/account 不能依赖它当前内容，需按日重算。
5. `master` 是当前快照（survivorship + 配置）。

## 2. Layer ② industry confirmation

### 纯计算入口

| 步骤 | 函数 | 位置 |
| --- | --- | --- |
| RPS metrics（全历史） | `metrics.compute_all_metrics(combined)` | `src/sw_industry_rps/metrics.py:51` |
| metrics 加载 | `storage.load_metrics(...)` | `src/sw_industry_rps/storage.py` |
| 重点行业明细 | `confirmation.compute_focus_snapshot(metrics_df, date=None)` | `src/sw_industry_rps/confirmation.py:105` |
| 群共振/主题/bucket/背离 | `classify_group_resonance` / `compute_theme_resonance` / `compute_bucket_resonance` / `classify_divergence` | confirmation.py:175/229/288/349/362 |

关键事实：
- **`compute_focus_snapshot` 已内置 `date` 参数**（None 才用 metrics 最新日）——纯函数层已支持历史日期。
- RPS metrics 存于 `data/processed/sw_industry/industry_daily_metrics.csv`（**1999→2026 全历史，124 行业**）→ Replay 无需重算 metrics，直接按日期切片。
- FOCUS_INDUSTRIES / THEMES / BUCKETS 模块加载时从 `themes_cfg.load_buckets()` 派生（confirmation.py:31/45/60）——config 驱动，可做 config_hash。

### drilldown 耦合（Replay 爆炸点）

- `cmd_confirm`（cli.py:1139）在 snapshot 之后做成分股穿透（`sw_contribution.compute_drilldown`，每行业 sleep 4s，网络/限频）。
- **信号字段（strength_level / resonance / RPS）与 drilldown 完全可分离**——Replay 跳过 drilldown 不影响信号。

### CLI 缺口

- `industry confirm` **无 `--date` 参数**（cmd_confirm 固定用 `metrics_df["trade_date"].max()`）。纯函数已支持，CLI 需补——Replay 未依赖此缺口（直接调用纯函数）。

## 4. 已实现约束（src/replay/）

| 模块 | 内容 |
| --- | --- |
| `schema.py` | 17 列 schema；`RULE_VERSION="v0.4.3"`；`config_hash` = 四个配置文件（themes/stock_universe/sw_rps/黑名单）sha256 |
| `engine.py` | `replay_single_date(date)` 纯离线三层重放；as-of 截断；个股趋势 `persist=False` 内存计算 |
| `parity.py` | 数值容差 0.02；状态字段必须完全一致；缺正式产物层 → `not_checked` 不计入 ok |
| `cli.py` | `replay single|parity --date` |

### 实现中的关键修正（避免重踩）

1. `build_stock_metrics` 增加 `persist` 参数（默认 True）——Replay 传 False，避免覆盖正式 `selection_inputs` 产物。
2. **Layer1 rps15 必须从 rotation_df 全精度取**（不是 account/watchlist 的 1 位舍入值），否则与正式 rotation parquet 对比超容差。
3. 重放行数值列先 `pd.to_numeric(errors="coerce")` 再落 parquet，避免 schema 默认 `""` 与 float 混型导致 pyarrow 报错。
4. `trend_engine.build_logger` 需要字符串级别，Replay 传 `logging.getLevelName(logger.level)`。
5. parity 的 ok 判定：只有「重放有行 且 正式产物存在」的层参与验收；缺正式产物的层（如 20260731 无 selection）不判 FAIL。

## 5. P0-7（日期区间循环）前置检查

- 单日期引擎 + parity 门禁已具备。
- Layer2 无需重算 metrics（1999→2026 全历史切片）；Layer1 需对每个日期重算横截面（`compute_cross_sectional` 只保留 tail 21 行，**全历史横截面需逐日调用或改造**——这是 P0-7 的主要成本点）。
- 股票/ETF 上市期与 as-of 截断天然兼容（未上市资产当日无数据，不会产生信号）。
- ETF 幸存者偏差：master 当前快照，历史横截面会缺退市/新上市标的（已识别，处理策略见计划 §9）。
