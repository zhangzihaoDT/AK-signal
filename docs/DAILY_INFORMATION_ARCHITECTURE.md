# 日报信息架构与展示契约

2026-10-28 · v0.7.3 · 布局 `daily_observation_modules_v13` · 契约 `daily_display_contract_v1`

本文固定日报的展示契约：每个模块默认展示什么、什么进入详情、什么只在审计产物中。契约只约束渲染，不选择、不重排、不重算任何事实。机器可读副本写在 `src/observation/contract.py`，并随每份日报写入 `observation_{date}.json` 的 `display_contract` 字段。

## 三层阅读

| 层 | 位置 | 回答 |
|---|---|---|
| Summary | `#summary` 今日市场速览 | 今天发生了什么、哪里需要继续观察 |
| Observation | `#market-environment` 01 → `#data-quality` 05 的默认表格 | 核心指标、横向比较、变化与状态 |
| Evidence | 各面板 `<details>`、`#stock-group-*`、技术详情 | 原始数值、完整指标、计算口径、来源与审计 |

Summary 由下方已验收事实按固定模板生成（代表指数当日涨跌、活跃研究主线条数、指数/行业/ETF 的计数与方向），不含预测、评分或买卖判断；HTML 中标注“展示摘要”。

## 三条通用规则

1. **默认展示关键对象，允许展开全量。** 行业 128 个、ETF 1339 只不在首页全部展开；展开区行数与总数分离显示（例如“展开其余行业 113 个”）。详情中的表格逐行只出现一次。
2. **异常优先。** 正常来源、正常日期和可用状态不再逐行重复；缺失、滞后、口径异常与已知限制集中在 05 “本次需关注的质量限制”，正常记录进入技术详情。
3. **原始数据、计算指标、展示指标分离。** 本版只改动 Report 的渲染与信息架构，不改变行情管道、指标计算与研究信号规则。

## 关键口径保持不变

- **ETF 位置**：默认补充 120日位置作为中期观察列，但**底部标签仍按原 120/360 日低位规则判定**，旧定义保留在计算层，面板与详情均注明。360日位置留在详情。
- **ETF 分类范围**：只代表已分类样本。03 面板与数据质量均展示“已分类 N 只 / 未分类 M 只”，分类结果不等于全部 ETF 市场。
- **同主题产品**：银行ETF×12、红利低波×9 等重复来自按产品排序；默认表与详情中标为“同主题产品折叠（名称推断，非跟踪指数映射）”，底层逐产品计算，不合并。
- **研究主线**：趋势阶段描述当前结构（绝对水平与条件），观察变化描述相对上一有效观察日的变化，两者分列。“已有机会 / 新增机会”在展示层更名为“已有观察线索 / 新增观察线索”，事实字段不变。
- **NO_SETUP**：不是活跃观察期，启动状态列显示“本档无启动候选，未形成 WATCH 观察期”，不写成 `NO_SETUP · 无启动候选` 以免被读成确认的弱势。
- **ETF 位置默认行**：按既有优先级排序后取前 20 行（位置变化初筛），不是“当天所有底部变化”；进入/离开底部的完整列表需展开。是否改为“位置变化事件优先”留待后续决定，本版不隐式改变排序。
- **个股趋势分**：仅保留为详情字段（活跃定义仍为趋势分 ≥70），不在主表重复展示。

## 行业变化观察（事件提取）

从两份已验收的行业快照派生，不新增指标：

- 首次进入 RPS15 前 20（当前排名 ≤20 且上一快照 >20）；
- 首次进入前 20 且转入“已形成趋势”；
- 趋势退潮（转入“正在退潮”）；
- 其余：全表阶段转换数与 RPS5 变化数。

前一日快照来自登记表 `config/observation_snapshots.json`，只登记已发布批次的 `industry_rotation_{date}.parquet`（仓库相对规范名与摘要）；build 只产出候选，发布阶段才提交。对照要求：行业代码集合一致、源交易日唯一、快照阶段可由现行 `classify_trend_stage` 复现。任一条件不满足即输出“无法判定”并写明原因，**不补造前一日排名或阶段，也不从原始历史回填**。本版首次运行尚无旧登记，因此当天显示“无法判定”，从次日开始可对照。

职责按三段划分：**Build 计算、Validate 校验、Publish 提交**。

- **Build** 在批次私有暂存区写出候选 `run_day/industry_snapshot.json`（版本、交易日、公布目录规范名、facts 摘要），不修改正式登记表。批次仍可能失败，因此不留下登记痕迹。
- **Validate** 只校验候选：版本与交易日对齐、规范名、摘要与本批 `industry_rotation_{date}.parquet` 逐字节一致，且候选回执与文件的 sha256 一致。历史登记表必须可解析（变化观察的对照来源）；不可解析只把变化观察降级为“无法判定”并写入验收提示，不阻断事实发布——变化观察是已验收事实的下游对照，不是事实成立的条件。
- **Publish** 是唯一写入正式登记表 `config/observation_snapshots.json` 的阶段：指针切换后按候选提交，事实从公布目录读回并重新核验摘要，只登记读者真正能看到的那份文件。写入是幂等且原子的：同一条目已存在则不改动；提交若在指针切换与登记之间中断，下一次运行按已发布批次的候选与回执补登。

解析只认摘要一致的文件：公布目录中的文件必须与登记摘要一致才算已验收快照。同一交易日的旧条目只可能来自更早的未完成尝试，发布时按本批候选重写；早于本交易日的登记缺失仍是硬失败——静默丢弃历史会改变“前一日快照”的含义。登记表是批次在运行中提交的状态，不纳入实现签名（`src/common/batch_release.py` 的 `SELF_WRITTEN`），否则发布写登记会让签名在批次收尾时变化。

2026-10-29 的 20261028 失败即旧实现的后果：build 直接写登记表，失败批次留下的当日条目指向已消亡的暂存路径，被当成“历史快照缺失”硬失败；放开之后，同一写入又造成签名漂移。收敛写入权到发布阶段同时消除了这两个缝隙。

## v0.7.3 Patch：确定性与口径

- **分类口径**：空白、NaN 与 `unclassified` 一律为未分类；已分类总数只取确有分类的产品。分类器的“其他”兜底行不是类别而是未分类池，分类概览不列出，使类别合计等于已分类样本；未分类样本只在说明与逐产品表中出现。
- **排序**：排名键按数值、代码键按文本，稳定排序，并列按代码；字符串化的 RPS 或整数代码不再改变先后。
- **覆盖率**：05 覆盖卡片与 JSON `modules` 使用同一份模块回执，不在缺失时填“—”。
- **摘要**：每个读数只出现一次；主线条目不与上方文字重复。
- **行业变化登记**：登记与解析以公布目录的规范名 `observation/industry_rotation_{date}.parquet` 为准，发布时重写；构建暂存路径不作为对照依据。

## 验收

`observation check` 在布局版本匹配时额外校验：五段结构与导航锚点、契约字段出现在默认表、详情字段不出现在默认表、指数与 IC 的逐行数值、行业变化事件边界（`verify_industry_events`）、本交易日快照候选的规范名与摘要同已验收事实逐字节一致、候选回执与文件一致。`observation_{date}.md` 镜像同一契约（速览、默认表、质量限制），技术详情折叠在 Markdown 的 `<details>` 中。
